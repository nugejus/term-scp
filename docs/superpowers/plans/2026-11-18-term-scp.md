# term-scp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A two-pane (local | remote) terminal file-transfer tool, `term-scp host:path`, with keyboard and mouse control, concurrent pipelined SFTP transfers, and an MVC structure that later admits delete, rename and remote↔remote.

**Architecture:**
- System `ssh` is the transport. ControlMaster means you authenticate once.
- `russh-sftp` speaks SFTP over each ssh process's stdin/stdout.
- A tokio runtime does all I/O.
- The main thread runs a synchronous ratatui loop, fed by one `std::sync::mpsc` channel that carries terminal input and I/O results.
- MVC:
  - Model = plain data.
  - View = pure render plus a hit-test cache.
  - Controller = events → `Command` → model mutation and I/O dispatch.

**Tech Stack:**
- Rust 2024 (rustc 1.96)
- ratatui 0.30.2. Use its `ratatui::crossterm` re-export (crossterm 0.29); no direct crossterm dependency.
- russh-sftp 3.0.1, tokio 1.54, clap 4.6 (derive)
- unicode-normalization 0.1.26, unicode-width 0.2, chrono 0.4 (`clock` only)
- tempfile 3.27 (dev)

**Spec:** `docs/superpowers/specs/2026-11-18-term-scp-design.md`. Read it before any task. The spec wins on behaviour; this plan wins on names and signatures.

## Global Constraints

**Crate and modules**
- Binary crate; `src/main.rs` is the only root (no `lib.rs`). **Every task that creates a module adds `mod <name>;` to `src/main.rs` before writing its tests.** Otherwise cargo never compiles the file and "Expected: FAIL" passes by accident.
- Crates: only those in the Tech Stack. chrono and unicode-width are already in the tree (via russh-sftp and ratatui); they replace hand-written timezone and width code.

**Conventions**
- UI strings are English.
- Paths are `String` with `/` separators on both sides. Local non-UTF-8 names go through `to_string_lossy` (`// ponytail: lossy non-UTF-8 local names`).
- Errors crossing module boundaries are `String`, shown verbatim in the status line.
- Nothing writes to stdout/stderr after the TUI starts. ssh stderr is always piped.
- Once a `Remote` exists, `main` returns an `ExitCode`. Never call `std::process::exit`: it skips destructors, which kill ssh and remove the control dir.

**SFTP I/O**
- Never call `flush()` on an SFTP writer; with the fsync extension it fsyncs. Finish writers with `shutdown()`.
- Copy loop: a hand-written 256 KiB buffer loop, not `tokio::io::copy`. That function writes 8 KiB at a time and starves russh-sftp's 16-deep write pipeline.
- SFTP timeouts:
  - handshake: `Config.request_timeout_secs = 600` (the user may be typing a password)
  - browse session: `set_timeout(30)` afterwards
  - transfer channels: `set_timeout(120)`
- File-type checks use mode bits only:
  - dir: `mode & 0o170000 == 0o040000`
  - regular: `== 0o100000`
  - symlink: `== 0o120000`
  - Never use russh-sftp's `FileAttributes::is_dir()/is_regular()`: they test bit containment, so sockets read as dirs.

**Transfers**
- At most 4 transfer jobs run at once; the rest wait FIFO. Use `tokio::sync::Semaphore` (fair).
- Partial files are named `<dest>.term-scp-part`.

**Look**
- Toolbar, in the user's order (this overrides the spec sketch): `New Dir`, `New File`, `Help`, `Move`, `Copy to`, `Change Dir`.
- Borders: focused = `Color::LightCyan` + `Modifier::BOLD` + `BorderType::Thick`; unfocused = `Color::DarkGray`, plain.
- Rows:
  - cursor in the focused pane: bg `LightCyan`, fg `Black`, bold
  - cursor in the unfocused pane: bg `DarkGray`
  - marked: bg `Color::Indexed(24)`, fg `White`

**Tests**
- Tests live in `#[cfg(test)] mod tests` inside each module.
- Async tests use `#[tokio::test(flavor = "multi_thread")]`, with every body wrapped in `tokio::time::timeout(30 s)`.
- Never call `std::env::set_var` (it is `unsafe` in 2024 and racy across parallel tests).
- Canonicalize every tempdir first (`let root = std::fs::canonicalize(tmp.path())?`) and build all paths and expectations from `root`. On macOS `/var` → `/private/var`.

## Review Focus

1. **Hangul or other wide filenames in a narrow pane.** The name column truncates by display width; size and time columns stay aligned. Task 7 test `wide_names_keep_columns_aligned`.
2. **Navigating while listings or transfers are in flight.**
   - A stale `Listed` reply must not overwrite the pane.
   - A refresh triggered by a finishing job must not cancel the navigation in progress.
   - Task 8 tests `stale_listing_is_ignored` and `refresh_during_navigation_keeps_target`.
3. **A directory symlink loop inside a copied tree.** The walk stops at depth 64 with an item error and the job finishes, on macOS as well (where ELOOP hits after 32 links per lookup). Task 5 test `symlink_loop_is_bounded`.
4. **FIFO/socket files inside an uploaded tree.** They are skipped with an item error and never opened, so nothing blocks. Task 5 test `fifo_is_skipped_not_hung`.
5. **Tiny terminals and very long cwd paths.**
   - Drawing at 20×5 and 1×1 must not panic in any UI state.
   - Titles keep the path's tail behind `…`, and the `(loading)` / `[disconnected]` suffix stays visible.
   - Task 7 tests `tiny_terminal_does_not_panic`, `long_title_keeps_tail`, `title_suffix_survives_long_path`.

```rust
pub struct SshOpts { pub port: Option<u16>, pub identity: Option<String>, pub options: Vec<String> }
pub struct Remote {
  pub label: String, pub home: String, pub sftp: russh_sftp::client::SftpSession,
  channel_argv: Vec<String>, child: std::sync::Mutex<tokio::process::Child>,
  stderr: std::sync::Arc<std::sync::Mutex<String>>, stderr_seen: std::sync::atomic::AtomicUsize,
  control_dir: Option<std::path::PathBuf>,
}
impl Remote {
  pub async fn connect(label: &str, argv: &[String], channel_argv: Vec<String>) -> Result<Remote, String>;
  pub async fn connect_ssh(host: &str, opts: &SshOpts) -> Result<Remote, String>;
  pub async fn open_channel(&self) -> Result<Remote, String>; // spawns channel_argv; same label/home/channel_argv; control_dir None
  pub fn alive(&self) -> bool;                                 // child.try_wait() is Ok(None)
  pub fn stderr_tail(&self) -> String;                         // last non-empty stderr line
  pub fn take_new_stderr(&self) -> Option<String>;             // last non-empty line written since the previous call
}
impl Drop for Remote { /* if control_dir is Some: remove_dir_all, ignoring errors */ }
pub fn ssh_argv(host: &str, opts: &SshOpts, control: &str, master: bool) -> Vec<String>;
pub fn sftp_err(e: russh_sftp::client::error::Error) -> String; // Error::Status(s) → s.error_message; else e.to_string()
#[cfg(test)] pub fn sftp_server_path() -> String;  // first existing: /usr/libexec/sftp-server, /usr/lib/openssh/sftp-server, /usr/libexec/openssh/sftp-server, /usr/lib/ssh/sftp-server
#[cfg(test)] pub async fn test_remote() -> Fs;     // Fs::Remote(Arc::new(Remote::connect("test", &[p.clone()], vec![p]).await.unwrap()))
```

**`connect`**
1. Spawn `argv` with `kill_on_drop(true)` and stdin/stdout/stderr piped.
2. Spawn a tokio task that appends stderr lines into `stderr`; keep its `JoinHandle`.
3. Run `SftpSession::new_with_config(tokio::io::join(stdout, stdin), Config { request_timeout_secs: 600, ..Default::default() })`.
4. On success:
   - `set_timeout(30)`
   - `home = canonicalize(".")`
   - set `stderr_seen` to the current buffer length, so `take_new_stderr` only reports later output
5. On failure:
   - `tokio::time::timeout(2 s, stderr_task)`; the task ends at stderr EOF, so every line is stored. Waiting for the child to exit is not enough.
   - Return the trimmed `stderr` if non-empty, else `sftp_err(e)`.

**`connect_ssh`**
- Create the control dir `/tmp/tscp-{pid}-{nanos}` with `std::os::unix::fs::DirBuilderExt::mode(0o700)`. `/tmp` keeps the socket path under 104 bytes regardless of `$TMPDIR`.
- `control = "{dir}/cm"`.
- Call `connect(host, &ssh_argv(host, opts, control, true), ssh_argv(host, opts, control, false))`.
  - On Ok, set `control_dir`.
  - On Err, `remove_dir_all(dir)` (ignore errors) before returning the Err.

**`ssh_argv`**, exact order:
1. Mux options:
   - master: `ssh -o ControlMaster=yes -o ControlPath=<c> -o ControlPersist=no`
   - channel: `ssh -o ControlMaster=no -o ControlPath=<c> -o BatchMode=yes`
2. Both forms: `-o ForwardX11=no -o ForwardAgent=no -o PermitLocalCommand=no -o ClearAllForwardings=yes -o RemoteCommand=none -o RequestTTY=no`. These are what sftp(1) and scp(1) pass. ssh keeps the first value given, so a user config with `RemoteCommand` or `RequestTTY force` can't break the binary pipe.
3. Then `[-p <port>] [-i <identity>] [-o <opt>]... -s <host> sftp`.

`BatchMode` on channels guarantees that a failed mux never prompts while the TUI is up.

**Remote arms**
- `channel`: on `open_channel()` Ok, `set_timeout(120)` and wrap it; on Err, return `self.clone()`.
- `list`: `canonicalize(path)`, then `read_dir`.
  - Entries whose mode is a symlink get their attrs replaced by `metadata(full)`; keep the lstat attrs if that fails.
  - `mode` = `permissions.unwrap_or(0)`. `is_dir` from mode bits. `size` = `size.unwrap_or(0)`. `mtime` = `attrs.mtime.map(i64::from)`.
- `stat`: `Err(Error::Status(s))` with `s.status_code == StatusCode::NoSuchFile` → `Ok(None)`.
- `create_new`: `open_with_flags(CREATE|EXCLUDE|WRITE)`, then `close()`.
- `create_write`: `open_with_flags(CREATE|TRUNCATE|WRITE)`.
- `set_mode`: `FileAttributes { permissions: Some(mode & 0o7777), ..FileAttributes::empty() }`.
- `replace`: if `self.stat(dest)` is `Some`, `self.remove_file(dest)`; then `self.rename(part, dest)`. Plain SFTP rename fails onto an existing file (spike-verified).

Behaviour (the spec's Operations section is normative):

**`submit`**: emit `Queued`, then spawn a task that acquires a permit (held for the whole job), emits `Started` and runs `run_job`.

**`run_job`**
1. `src.channel().await` and `dst.channel().await`.
2. **Scan** each item into ops: `Dir{src,dst}`, `File{src,dst,size,mode}`, `DirDone{src}` (post-order, Move only).
   - **Names, not paths:**
     - A top-level item's dst = `join(parent(dst).0, dst_name_for(basename(dst)))`.
     - A child's dst = `join(dst_dir, dst_name_for(name))`.
     - Existing destination parent dirs are never rewritten, because they may be NFD on the server.
   - **Walk from canonical paths:** recurse into a dir via `src.list(path)` and build child src paths from the *canonical* path it returns (`join(canonical, name)`). That way each lookup crosses at most one symlink, and the depth cap (not the kernel's ELOOP, which on macOS fires after 32 links) ends loops.
   - **Bad entries:**
     - Depth > 64 → `ItemError("too deeply nested (symlink loop?)")`, subtree dropped.
     - Neither a dir nor `is_regular()` → `ItemError("not a regular file")`, skipped and never opened.
3. Emit `Scanned`.
4. **Execute** the ops in order:
   - **`Dir`** → `stat(dst)`:
     - a dir → ok (merge)
     - a file → `ItemError("destination exists and is not a directory")`, skip the subtree
     - None → `mkdir`
   - **`File`** → `stat(dst)`:
     - a dir → `ItemError("destination is a directory")`
     - a file → unless overwrite-all is set, emit `Conflict` and await the reply; a dropped sender counts as `Cancel`
       - `Skip` → `skipped += 1`
       - `Cancel` → stop, finish with `cancelled = true`
     - Then `write_via_part`. On success with `mv`: `src.remove_file(src)`.
   - **`DirDone`** → `remove_dir(src)` only if no failed or skipped src path lies under it (`// ponytail: O(n²) prefix scan, fine for thousands of items`).
5. Progress: at most 1 event per 100 ms per job, plus one final event. Skipped and failed files add their size to `done_bytes`.

**`write_via_part`**
1. `create_write(part)`, where `part = dest + ".term-scp-part"`.
2. Copy in a 256 KiB loop, calling `on_bytes(n)`.
3. `shutdown()`, then `set_mode(part, mode)`.
4. On an error in steps 1–3: `remove_file(part)` (ignore its result) and return Err. `dest` is untouched.
5. `replace(part, dest)`. On Err, call `stat(dest)`:
   - `Some` (original intact, or the rename landed) → `remove_file(part)` and return Err.
   - `None`, or the stat fails → **keep the part**, because it may be the only complete copy. Return `Err("{dest}: {e} (new content kept in {part})")`.

### Task 9: Controller — mouse

**Files:**
- Modify: `src/controller.rs`

**Interfaces:**
- Consumes:
  - from Tasks 6–7: `App.hit`, `App.drag`, `App.last_click`, `Pane.offset`, `TOOLBAR`, `view::draw`
  - from Task 8: `apply`, `submit_copy`
- Produces: `fn on_mouse(&mut self, app: &mut App, m: ratatui::crossterm::event::MouseEvent)`, called from `handle`.

Rules:
- **Gate:** ignore all mouse events while a popup is open or `conflicts` is non-empty.
- **Row under the pointer:** `pane.offset + (y − hit.panes[s].y)`, when `(x, y)` is inside `hit.panes[s]` and the index is < `entries.len()`.
- **`Down(Left)` on `hit.toolbar[i]`** → `apply(TOOLBAR[i].1)`.
- **`Down(Left)` on a row:**
  1. `focus = s` and `cursor_to(idx)`.
  2. Double-click: if `last_click` is `(t, s, idx)` with `now − t < 400 ms` → `apply(Enter)` and clear `last_click`; else record it.
  3. `drag = Some(Drag { from: s, items, active: false })`. `items` are fixed now: `selection()` if `entries[idx].name` is marked, else `[entries[idx]]`, or empty when that is `..`. This way a refresh mid-drag can't change what is copied.
- **`Drag(Left)`** with a drag → `active = true`.
- **`Up(Left)`:**
  - If the drag is active, its items are non-empty, and the pointer is inside the other pane:
    - target = `join(other.cwd, row.name)` when the row under the pointer is a dir other than `..`, else `other.cwd`
    - `submit_copy` pairs `(join(src.cwd, n), join(target, n))` with `mv = false`
  - Always set `drag = None`.
- **`ScrollUp` / `ScrollDown`** over pane s → `move_cursor(∓3/±3, false)` on that pane. Focus doesn't change.

### Task 10: Wire `main`, terminal lifecycle, pty smoke test

**Files:**
- Modify: `src/main.rs`
- Create: `tests/fake-ssh/ssh` (executable), `tests/smoke.exp`

**Interfaces:**
- Consumes: all of the above. `SshOpts` is built from `Cli { port, identity, ssh_option }`.

`fn main() -> std::process::ExitCode`, in order (spec: Connection):
1. `Cli::parse()`, then `parse_target`. On Err, print it to stderr and return 2.
2. Build a multi-thread `tokio::runtime::Runtime`.
3. `rt.block_on(Remote::connect_ssh(&t.host, &opts))`. On Err, print `"term-scp: cannot connect to {host}:\n{err}"` and return 1. This runs **before** raw mode, so ssh's password, passphrase and host-key prompts work.
4. Resolve the start dirs:
   - remote: `canonicalize(remote_start(&t.path))`
   - local: `--local` or `current_dir()`, through `std::fs::canonicalize`
   - On Err, print it and return 1. Returning (not `exit`) drops `Remote`, which kills ssh and removes the control dir.
5. Terminal setup:
   - Install a panic hook that runs `DisableMouseCapture`, then chains the previous hook.
   - `let mut terminal = ratatui::init();` (it adds its own restore hook).
   - `execute!(stdout(), EnableMouseCapture)`.
6. Input thread: `while let Ok(e) = event::read() { if tx.send(AppEvent::Input(e)).is_err() { break } }`.
7. Build the app:
   - left = `Pane::new(Fs::Local, local)`
   - right = `Pane::new(Fs::Remote(Arc::new(remote)), remote_cwd)`
   - `App::new(left, right, !no_icons)` and the `Controller`; `load` both panes
8. Loop until `app.quit`:
   1. `terminal.draw(|f| view::draw(f, &mut app))`
   2. `match rx.recv_timeout(100 ms)`: `Ok(ev)` → `handle`, then drain `try_recv()` into `handle`; `Timeout` → nothing.
   3. Then, **every iteration**, `ctl.tick(&mut app, Instant::now())`. `sample` throttles itself, and progress events would otherwise starve a timeout-only tick.
9. Teardown:
   1. `execute!(stdout(), DisableMouseCapture)`, then `ratatui::restore()`.
   2. `{ let _g = rt.enter(); drop(app); drop(ctl); }`, then `rt.shutdown_background()`.
   3. Return 0.
